PolySim — Developer Handoff PAPER ONLY replication brief

Prediction-market insider-detection & paper copy-trading simulator · Polymarket-only · self-hosted single-operator · designed to run on a small Linux VPS.

Scope of this document: everything a developer needs to replicate the application architecture, deploy it on a VPS, and operate it. Strategy-performance numbers, P&L, and balances are intentionally out of scope — they're separate operational data, not part of the build.

1. What PolySim Does

PolySim ingests every trade on Polymarket, ranks wallets by skill-weighted P&L to build a "cohort" of the top performers, then mirrors every BUY and SELL those wallets make into paper portfolios. When a cohort wallet exits, we exit. No real money is ever placed — every order is simulated against a captured order-book snapshot with realistic fill, slippage, and settlement-delay modelling.

The product is permanently paper-only: a CI grep (scripts/ci_safety.py) refuses to ship if any code path reaches a live order-placement API. Spec §2 and §16 forbid live trading.

3. Components

  • IngestPipeline — WebSocket subscriber for live trades, Gamma REST for market metadata, Alchemy event-log scraper for the CTF (Conditional Tokens Framework) when WS lags.
  • DiscoveryRefreshLoop — every 6 hours, extracts ~30 features per wallet using Polars, runs a sigmoid-logistic classifier (no LLM), selects the top N by skill-adjusted P&L, writes them into the cohort table. The cohort drifts as new whales surface in the ingest stream.
  • CopyOnCohortLoop — the strategy. Polls trades on a 15s watermark. Each cohort BUY above the configured minimum notional becomes a synthetic flag. Each cohort SELL closes the matching paper position at the cohort's exit price, booking realized P&L.
  • ScoringLoop — legacy detector-based scoring (CategoryInsider, EventInsider, Coordination, Timing, FreshWallet). Disabled by default after calibration; kept in the tree for experimentation.
  • Dispatcher → ProfilePaperExecutor — fans each flag to N paper runs (one per risk profile). The executor applies market-side filters (volume, odds bounds), position sizing (fixed/percentage/kelly), depth-cap, drawdown-gate, daily-loss gate, then simulates a fill against the most-recent orderbook snapshot via the walk-the-book FillModel.
  • FillModel — log-normal detection + decision latency, partial fills on thin books, configurable slippage_ticks. Spec §7.7 caps fill price at best_ask + slippage_ticks * tick_size.
  • SettlementSweepLoop — Polymarket settles on Polygon (~2s blocks). Every fill enters a 2-block "pending_until" window where its capital is locked, reproducing capacity-lock cycles observed in production logs.
  • Kill switches — flag-rate (anomalous burst → run pause), per-run drawdown limit, daily-loss limit, ingest stall (no trades for 5 min → watchdog alert).
  • Reporter / Telegram bot — daily summary scheduler (push), inbound bot with /status /runs /run /flags /compare /report commands, watchdog stall alerts.
  • Web dashboard — read-only 5-panel SPA at port 8765, polls SQLite directly, refreshes every 2s.

4. Database

SQLite single-file (polysim.db). Migrations in src/polysim/db/migrations/0001_init.sql through 0007_empirical_priors.sql. Core tables:

  • trades — every fill observed (id, wallet, market, side, outcome, size, price, timestamp).
  • markets — Polymarket market metadata + resolution outcome.
  • wallets_discovery — cohort registry with classifier scores per niche, frozen per experiment.
  • flags — alpha signals (synthetic CohortCopy + legacy detector composites).
  • paper_runs · paper_positions · paper_fills — per-run trading state.
  • experiments — pre-registered experiment containers with cohort SHA256 hash.
  • orderbook_snapshots — captured order-book depth used by the fill model.
  • settlement_events — per-fill 2-block settlement window tracking.

5. Strategy Calibration Notes

After the initial 90-day backtest, three calibrations were folded into the default configuration. A replicating dev should ship these as defaults, not as flags to opt into:

  1. Niche weighting = 1.0 (was 1.5). NICHE_WEIGHT in src/polysim/trading/consensus.py. Per-niche pools (aec, ai_labs, creator_econ) produced no measurable edge in the resolved-market sample; the general "top by skill" pool carried the result.
  2. Category filter on politics + sports in the cohort-copy path. politics and sports were added to both config.yml categories and the Market.category Literal in src/polysim/models.py. A backfill classifier (scripts/classify_markets_backfill.py) retags existing markets.
  3. SELL mirror in CopyOnCohortLoop. Cohort SELLs close any matching open paper position (market, outcome, source_wallet) at the cohort's sell price. Required adding CohortCopy to the allowed_detectors list in profiles/degen.yml and profiles/medium.yml.

6. Daily Trade Volume

Measured during healthy ingest, Polymarket pushes ~19,000 trades per day across all markets. Cohort intersection (typically 200–300 whales) covers roughly 15% of that flow. After the strategy's notional-floor + category filters, that thins to a few hundred actionable signals per day. Capacity-plan around those numbers.

7. Running on a VPS

Minimal requirements for a single-operator deployment:

  • OS: Ubuntu 22+, Debian 12+, or any modern Linux. Repo also runs on Windows 11 (where it was developed).
  • Python: 3.12 or 3.13 with uv or stdlib venv.
  • Disk: SQLite DB grows ~150 MB per million trades. Reserve 50 GB for several months of ingest + backfill.
  • RAM: 2 GB minimum; 4 GB recommended (Polars feature extraction is memory-hungry on cohort-refresh ticks).
  • CPU: 2 vCPU is fine; the workload is I/O bound.
  • Network: persistent outbound to clob.polymarket.com (WS), gamma-api.polymarket.com (REST), polygon-mainnet.g.alchemy.com (RPC), and api.anthropic.com if using the Tier-2 LLM investigator.

7.1 First-time setup

# 1. Clone the repo
git clone <your-fork> polysim && cd polysim

# 2. Python env (uv is fastest)
uv venv .venv && source .venv/bin/activate
uv pip install -e ".[dev]"

# 3. Secrets (.env at repo root)
cat > .env <<'EOF'
ALCHEMY_API_KEY=your_alchemy_key
ANTHROPIC_API_KEY=your_anthropic_key          # optional, only if using LLM investigator
TELEGRAM_BOT_TOKEN=your_bot_token             # optional
TELEGRAM_CHAT_ID=your_chat_id                 # optional
EOF

# 4. Initial DB + schema
python -m polysim.cli init

# 5. Build the cohort (one-time, ~30 min wall clock)
python -m polysim.cli ingest backfill --days 90 --max-markets 2000
python -m polysim.cli ingest backfill-closed --max-markets 10000
python -m polysim.cli discovery run --experiment-id experiment_001

# 6. Sanity check
python -m polysim.cli doctor

7.2 Running under systemd

Create /etc/systemd/system/polysim.service:

[Unit]
Description=PolySim live paper-trading orchestrator
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=polysim
WorkingDirectory=/home/polysim/polysim
EnvironmentFile=/home/polysim/polysim/.env
ExecStart=/home/polysim/polysim/.venv/bin/python -m polysim.cli live \
    --profiles systematic,degen \
    --tag experiment_001
Restart=on-failure
RestartSec=10
StandardOutput=append:/home/polysim/polysim/logs/live.log
StandardError=append:/home/polysim/polysim/logs/live.err.log

[Install]
WantedBy=multi-user.target

Web dashboard as a second service:

[Service]
ExecStart=/home/polysim/polysim/.venv/bin/python -m polysim.cli web \
    --host 0.0.0.0 --port 8765
Restart=on-failure

Enable and start:

sudo systemctl daemon-reload
sudo systemctl enable --now polysim.service polysim-web.service
sudo systemctl status polysim          # check health
journalctl -u polysim -f               # tail logs

7.3 Reverse proxy

The web dashboard binds to 0.0.0.0:8765 with no auth. Don't expose that directly. Front it with Caddy or nginx with basic-auth: 

# Caddyfile
polysim.your-domain.com {
    basicauth {
        you JDJhJDE0JG... # caddy hash-password
    }
    reverse_proxy 127.0.0.1:8765
}

12. Known Operational Caveats

  1. Resolution lag: Polymarket markets typically take weeks-to-months to resolve. Most positions are MTM-only at any given snapshot — plan reporting accordingly.
  2. WS reconnection is opportunistic. If the WS drops silently the orchestrator needs a restart. systemd Restart=on-failure handles process crashes but not every silent stall — pair it with the UptimeWatchdog (ingest stall → Telegram alert).
  3. Data-API pagination cap: the public trades endpoint returns HTTP 400 past offset ≈ 3500. The PolymarketREST.get_trades wrapper treats that as EOF. Document this if you rewrite the client.
  4. Live trading is architecturally prohibited. The CI grep is not optional; it's the operator's protection against accidentally shipping a live order path.
  5. Cohort drift: if you stop running DiscoveryRefreshLoop, the cohort decays. The experiment harness assumes a refresh interval no longer than 24h.
